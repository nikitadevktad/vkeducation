# Практическое задание №9. Kotlin Coroutines и Structured Concurrency

## Установка приложения

Состояние установки представлено `InstallState`: приложение может быть не установлено, устанавливаться с прогрессом от 0 до 100 или быть установленным. `AppDetailsViewModel` хранит это состояние в `StateFlow`. При нажатии запускается корутина `viewModelScope.launch`, которая обновляет прогресс каждые 150 мс.

`viewModelScope` привязан к жизненному циклу ViewModel, поэтому работа отменяется при её уничтожении. Ссылка `Job` нужна для отмены установки по повторному нажатию. `cancel()` прекращает задержку и выполнение корутины без блокирования главного потока. Счётчик поколения установки дополнительно не позволяет отменённой корутине записать устаревшее состояние.

Structured concurrency используется и для установки, и для рейтингов: дочерние корутины принадлежат `viewModelScope` или `coroutineScope` и автоматически отменяются вместе с родительской задачей.

## Загрузка рейтингов

Последовательный вариант вызывает источник рейтинга для каждого id по очереди. Параллельный вариант создаёт дочерние задачи через `async` внутри `coroutineScope` и ожидает их через `awaitAll`; ошибка или отмена распространяется на всю операцию.

| Способ | Количество приложений | Время |
| --- | --- | --- |
| Последовательный | 15 | Измеряется в интерфейсе на устройстве или эмуляторе |
| Параллельный | 15 | Измеряется в интерфейсе на устройстве или эмуляторе |

При одинаковой задержке источника последовательный вариант ожидает все 15 запросов по очереди, а параллельный — выполняет их конкурентно, поэтому обычно заметно быстрее. Значения в таблицу следует занести после измерения в запущенном приложении; виртуальное время unit-тестов для этого не используется.
